# 小优身份、任务送达与响应速度审计（2026-08-13）

## 结论

本轮三个现象来自三个独立底层断点，不是模型随机波动：

1. 李老师重置会话后被称为金总：企业微信身份识别正确，但共享 `MEMORY.md` 混入老板个人信息；新会话缺少足够强的当前人身份契约，最终回复也没有称呼校验。
2. 任务创建成功但李老师没有及时收到：任务通知已进入 outbox，但 Hermes v0.20 不支持旧的 `post_gateway_start` 插件钩子，常驻 drain worker 实际没有启动；通知直到 21:00 日报进程顺带 drain 才发送。
3. 回复常需十几秒：主要成本来自工具参数校验失败引发的额外模型轮次，以及金总、李老师长会话上下文持续膨胀。生产压缩阈值和最大输出配置过于宽松。

## 修复

- 可信企业微信身份在每轮显式注入，当前人姓名优先于共享记忆和旧会话。
- 非老板会话的错误开头称呼增加最终守卫，只修直接称呼，不改正文中合法的“金总安排”。
- 共享长期记忆改成中性边界；个人身份、偏好和任务只从身份隔离账本读取，原文件先归档再替换。
- 模型不再必填 `user_id` 和 `operation_id`；系统从可信会话注入，减少失败工具轮次且防止模型冒用身份。
- 新增独立 outbox path + timer worker：任务入队后立即唤醒，60 秒兜底；不再依赖日报进程。
- 收紧 Agnes 上下文、输出和压缩参数，降低长会话成本；不删除会话历史。
- 活跃会话缓存增加租户数据目录作用域，避免不同机构相同 user id 相互影响。

## 验收门禁

- 固定回归、语法检查、差异检查、敏感扫描、demo 租户验收全部通过。
- 生产上线后必须确认主服务、回调、outbox worker、path、timer 正常，无新增导入或运行错误。
- 不自动创建真实任务或主动外发。真实任务提醒时效和实际对话速度，由金总/李老师下一条自然测试验证。

## 剩余风险

- 老的超长会话第一次触发压缩时可能仍偏慢，压缩完成后的后续轮次才是稳定速度。
- 当前生产 SQLite 版本较旧的 WAL 能力告警仍是独立 P1，不属于本轮三个故障。
