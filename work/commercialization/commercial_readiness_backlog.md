# Hermes 商业化准备技术债清单 V1

目标：列出从“优益样板”走向“可交付产品”前必须处理的问题，避免带着数据串机构、配置写死、手工部署过重等风险去卖。

## P0：真实交付前必须解决

- 租户隔离：所有数据、Memory、Skills、H5 cache、日报、唤醒报告、审计账本必须按机构隔离。
- 密钥隔离：企业微信 Secret、Token、EncodingAESKey、H5 token 不能进代码库和模板。
- 优益资料剥离：新机构初始化包不得包含优益学生、老师、目标、聊天记录、老板偏好。
- tenant_id 配置化：替换代码中写死的 `youyi_tuoguan`。
- 机构事实文件配置化：不能默认读取 `youyi_operating_model.json`。
- 新机构验收脚本：必须验证 Hermes 不知道优益数据，并能正确识别新机构。
- 备份恢复：每家机构必须有独立备份和恢复流程。
- 权限回归：每家机构开通后必须验证老板、店长、老师权限和 H5 访问隔离。

## P1：影响交付效率，需要在试点前完成

- 新机构初始化脚本：根据 `tenant_profile.json` 生成数据目录、配置、Memory 初始文件、企业微信映射和 H5 权限。
- systemd 模板化：从 `hermes-youyi-*` 改为可参数化的单机构服务模板。
- Skill 模板化：从 `youyi-digital-employee` 拆成通用产品 Skill + 机构事实 Skill。
- 开通检查报告：自动输出新机构已知事实、缺失事实、权限、主动外发授权和风险。
- 商业化演示数据：准备一套不含真实个人信息的 demo 数据。
- 标准测试包：覆盖聊天、写入、日报、唤醒、H5、主动提醒、老师候选、权限。
- 版本升级清单：每次产品升级要知道哪些机构需要同步、哪些配置不能覆盖。

## P2：规模化后再做

- 中央运维后台：查看所有机构 Hermes 在线状态、日报状态、模型错误、外发失败、数据增长。
- 批量升级机制：先灰度一家，再批量升级。
- 多租户数据库：等客户数量和数据规模上来后再评估。
- 统一账单：按机构、老师数、学生数、主动消息量或高级能力收费。
- 客户成功看板：展示每家机构 Hermes 创造的续费、招生、记录、沟通和老师减负价值。
- 服务商企业微信模式：从每家内部应用手工配置，升级为更标准的第三方服务商接入。

## 当前不建议做的事

- 不建议现在重构成复杂 SaaS 多租户。
- 不建议现在把所有机构跑在同一份 Memory 里。
- 不建议直接复制优益生产目录给新客户。
- 不建议未验证优益稳定前大规模销售。
- 不建议开放老师/店长全员主动外发作为商业默认能力。

## 商业化阶段判断

当前阶段：优益样板打磨后期 + 商业化分层准备。

下一阶段目标：

- 优益持续稳定运行。
- 完成新机构配置模板。
- 完成优益专属剥离清单。
- 开始设计标准安装包和新机构初始化脚本。
