# 小优工作承诺、监督与自愈契约 V1

## 目的

小优不是只把工作“答应下来”。凡是它对人作出可执行的后续承诺，必须能在权威工作事项中找到计划、证据和终态；凡是出现投影、上下文或回执不一致，监督层必须留下可复现的发现和处理回执。

主链固定为：

`对话/唤醒 -> 工作事项 -> 承诺计划 -> 执行或等待 -> 证据核验 -> 终态 -> 监督复查`

模型继续决定业务判断、问题优先级和下一行动。系统不替模型写固定业务流程，只负责事实、权限、状态、幂等、审计、写后反查和安全边界。

## 权威状态

- `hermes_work_items.jsonl` 是工作根对象。`work_kind=conversation_commitment` 表示对话产生的工作承诺，不创建第二套任务系统。
- 承诺阶段为：`captured -> planned -> active -> waiting -> verifying -> completed`；异常终态为 `cancelled / expired / superseded / failed / escalated`。
- 已有正式任务、目标或机构工作事项时，承诺只关联现有对象，不重复创建业务事实。
- 没有创建或更新回执，小优不能说“我会自动推进”“已经整理好”或“已经安排”。

## 监督边界

监督运行器在 `:05` 和 `:35` 异步运行。先进行无模型确定性检查，只有确认异常时才允许受限的只读顾问审查。首个 7 天影子周期将 `HERMES_SUPERVISION_COUNCIL_ENABLED=0` 保持关闭；指标稳定后才打开，且只调用 Agnes、单次 8 秒、最多 3 个深度为 1 的无工具顾问。

监督输入只包含脱敏运行证据和权威对象引用，不保存聊天正文、密钥或家长隐私。首批检查：未落账承诺、无回执成功、任务与 H5 分叉、旧上下文复活、重复未发送候选、偏好未应用、身份参与人不一致、自主循环假成功和模型连续超时。

顾问角色只能提出建议：真实性、上下文与时间、任务执行闭环。它们没有企业微信发送、业务写入、文件、终端、定时器、会话搜索或嵌套委派权限；意见必须经过确定性证据核验，不能直接成为事实。

## 自动修复白名单

第一阶段仅允许以下低风险技术性修复：

- 重建 H5 缓存；
- 从权威对象重建或清理上下文投影；
- 作废同一指纹的未发送重复候选；
- 写入自我修正事件；
- 重新注入已验证的个人工作方式上下文。

每次修复必须写入 `RepairReceipt`：前置哈希、幂等键、影响资源、写后反查和复测结果。失败只记录失败或升级，绝不说已解决。

永远禁止自动修改：任务事实或关闭状态、制度、权限、工资、绩效、人员身份、生产代码、模型配置、systemd、数据迁移、真实外发和家长联系。

## 数据与可见性

新增内部账本：

- `supervision_runs.jsonl`
- `supervision_findings.jsonl`
- `supervision_repairs.jsonl`

老板 H5 的“小优”页只显示工作承诺、开放监督发现和已验证的低风险修复摘要。老师和店长看不到监督记录、顾问意见或其他人员信息。H5 仍然只读，讨论和任何业务动作回到企业微信与小优完成。

## 分阶段上线

1. 本地和影子环境验证后，生产先以 `HERMES_SUPERVISION_APPLY_REPAIRS=0` 只读运行 7 天。
2. 误报率低于 5% 后，仅打开白名单中的投影修复；仍不改权威业务事实。
3. 连续 7 天无身份串人、误改、重复外发、虚假成功或回滚失败，才评估扩大技术投影自愈范围。

任何 P0（跨人、未经授权外发、数据覆盖、非法任务迁移、连续服务失效）都会停止自动修复，仅保留只读监督和升级记录。
