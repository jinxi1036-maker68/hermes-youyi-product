# 小优 H5 V1 产品结构冻结稿

> 版本：V1.0
>
> 状态：已通过并冻结
>
> 冻结日期：2026-08-23
>
> 适用范围：示例机构托管当前生产 H5，以及后续可复制机构的 H5 V1
>
> 本文件只冻结产品结构，不修改 H5、Hermes 主链、生产代码或业务数据。

## 1. 冻结目的

本次冻结不是继续修补现有看板，也不是先画页面再找数据，而是先确定小优 H5 V1 的产品边界：

1. H5 在小优产品中承担什么职责。
2. 老师、店长、老板分别看到什么、为什么看、看完做什么。
3. 每项展示来自哪个真实数据源，哪些只是派生或 AI 候选。
4. 哪些旧模块保留、改造、隐藏或删除。
5. V1 不做什么，V1.1 和 V2 在什么条件下进入。

冻结稿确认后，页面结构不得在开发过程中随意扩张。新增一级页面、业务写操作、数据源或角色权限，必须先提交产品变更说明。

## 2. 产品定义冻结

### 2.1 正式名称

- 产品名称：**小优工作台**
- 老师副标题：**我的教学与服务工作**
- 店长副标题：**门店运营与协作**
- 老板副标题：**经营决策与小优进展**

以下名称不再作为 H5 主产品名：

- Hermes
- 托管 AI 看板
- 小优老师成长助手
- 小优数字员工工作台

“数字员工”是小优的产品定位，不需要反复作为界面技术名词出现。用户应通过小优整理重点、推进工作和提供证据的行为感受到它是一名数字员工。

### 2.2 正式产品定位

**小优工作台是企业微信内、由小优整理的角色化工作视图。它把真实业务账本、执行回执和小优的有证据判断，整理成用户当前需要关注的事项。**

它不是：

- 另一套 Hermes 控制台；
- 一套新的业务后台；
- 绩效排名系统；
- 老师填表系统；
- 把所有数据都放上去的传统 Dashboard；
- 独立于企业微信对话之外的第二个 AI 助手。

### 2.3 产品分工

| 产品层 | 唯一职责 |
| --- | --- |
| 企业微信 | 可信身份入口、自然对话入口、通知和人与小优的协作入口 |
| Hermes / 小优 | 理解、判断、辅导、选择工具、推进工作、自然交流 |
| Repository / 业务账本 | 保存权威事实、权限、任务状态、证据、回执和审计 |
| 小优工作台 H5 | 按角色展示当前重点、工作进展、可信证据和数据状态 |

H5 不复制 Hermes 的思考能力，不建立第二套任务状态，不在按钮后隐藏固定 Router。

## 3. 角色冻结

V1 只支持以下三个正式角色：

| 角色 | 服务目标 | 数据范围 | 主要感受 |
| --- | --- | --- | --- |
| 老师 | 减少遗漏、获得任务帮助、看清自己的学生与积累 | 本人负责的学生、任务、记录和个人工作材料 | 小优在帮我工作，不是在考核我 |
| 店长 | 发现现场异常、协调人员、保证任务和学生服务不断档 | 授权门店或项目范围内的学生、老师、任务和风险 | 小优帮我看店、找卡点、推动协作 |
| 老板 | 看经营重点、做取舍、确认小优是否真正推进 | 机构范围内的目标、经营状态、团队信号和执行证据 | 小优替我整理判断材料，不让我陷入流水账 |

家长报告继续使用现有独立、审核后可见的家长报告链路，不并入小优工作台 V1，也不作为第四种工作台角色。

## 4. 全角色共用框架冻结

三个角色只共用产品外壳，不共用相同的信息架构。

### 4.1 共用外壳

- 顶部：小优标识、`小优工作台`、当前角色、机构或项目名称。
- 数据状态：显示最后更新时间，以及“实时事实、派生结果、数据待补、已过期”等状态。
- 主体：按角色展示不同首页和一级入口。
- 底部：稳定的移动端底部导航，不使用横向滚动 Tab。
- 证据详情：统一使用底部抽屉或独立只读详情页。
- 行动出口：固定提供“返回企业微信问小优”。

### 4.2 共用数据表达

每一项重要内容必须能回答：

- 这是什么事实或判断；
- 来自哪里；
- 最后何时更新；
- 当前是否仍有效；
- 用户下一步应回企业微信问小优，还是只需查看。

缺失值不得显示为 `0`。必须区分：

- 当前没有问题；
- 尚未采集；
- 数据已过期；
- 当前角色无权限；
- 系统暂时读取失败。

### 4.3 共用交互边界

V1 允许在 H5 内进行：

- 切换已授权项目或日期范围；
- 搜索和筛选；
- 展开证据；
- 查看任务、学生、记录和执行状态；
- 复制已审核内容或链接；
- 返回企业微信继续问小优。

V1 不允许在 H5 内进行：

- 创建、取消或完成任务；
- 写学生记录；
- 联系老师、店长或家长；
- 修改工资、权限、制度或人员状态；
- 批准学习候选；
- 触发 Hermes 自主行动；
- 直接修改任何权威业务账本。

需要判断、确认或写业务的行为回到企业微信，由用户与小优自然沟通，小优再调用现有受控能力。

## 5. 老师工作台结构冻结

老师 V1 固定为三个一级入口。

### 5.1 一级入口一：今日

首页先回答：**今天我最需要关注什么，小优能怎样帮助我。**

固定结构：

1. 小优今日提示：最多 3 条，只使用当前且有证据的事项。
2. 当前任务：展示正在进行、等待补证据或即将到期的任务。
3. 重点学生：最多 3 名，并说明进入重点的真实原因。
4. 今日积累：今天已形成的有效记录或可复用材料。
5. 下一步：只给一个最容易执行的动作，复杂处理回企业微信问小优。

不得在首页展示老师排名、团队比较、工资估算或抽象绩效分数。

### 5.2 一级入口二：学生

默认不是完整通讯录，而是“当前需要关注的学生”。

固定能力：

- 只看本人负责且当前有效的学生；
- 默认显示需要关注、存在开放任务或近期缺少有效记录的学生；
- 可切换查看全部学生并搜索；
- 学生详情展示近期有效观察、开放任务、最近更新时间和证据来源；
- 不展示其他老师的私人记录或无权限信息。

### 5.3 一级入口三：我的积累

目标是让老师感受到小优在帮她沉淀工作，而不是给她打分。

固定能力：

- 最近形成的有效学生记录；
- 可复用的家长沟通材料；
- 已审核成长报告材料；
- 按学生或材料类型筛选；
- 私人月度工作总结，仅本人可见，不参与公开排名。

### 5.4 老师二级页面

- 任务详情与陪伴进度；
- 学生服务详情；
- 记录或材料证据详情；
- 个人月度总结。

## 6. 店长工作台结构冻结

店长 V1 固定为四个一级入口。

### 6.1 一级入口一：今日现场

首页先回答：**今天门店哪里可能断档，我应该先协调什么。**

固定结构：

1. 安全或服务异常；
2. 卡住、逾期或等待证据的任务；
3. 小优整理的 1 至 3 条现场建议；
4. 待店长确认或交接的事项；
5. 当前项目和数据更新时间。

只有真实异常或有证据趋势才能进入首页。没有异常时明确显示“当前未发现需要立即处理的异常”，不能用历史事项填满页面。

### 6.2 一级入口二：学生

固定能力：

- 查看授权门店或项目范围内的学生；
- 默认展示需要关注的学生；
- 查看责任老师、近期记录、开放任务和数据新鲜度；
- 按老师、项目和状态筛选；
- 不把学生数量本身包装成经营结论。

### 6.3 一级入口三：团队

团队页用于协作和支持，不做公开绩效排行。

固定能力：

- 查看授权范围内在职人员和数据状态；
- 显示“谁需要支持、为什么需要支持”；
- 查看开放任务、工作负荷和证据缺口；
- 区分在职、离职和状态待确认人员；
- 不展示工资、处罚或老师之间的公开排名。

### 6.4 一级入口四：任务

固定分组：

- 进行中；
- 等待证据；
- 已逾期；
- 最近完成。

任务详情展示来源、责任人、学生对象、目标、时间、证据要求和关闭状态。任务写操作继续在企业微信中由小优完成。

### 6.5 店长二级页面

- 学生服务详情；
- 老师支持详情；
- 任务和关闭证据详情；
- 暑假班等项目详情。

暑假班或其他项目是项目维度，不再为每个项目硬编码一套导航。

## 7. 老板工作台结构冻结

老板 V1 固定为四个一级入口。

### 7.1 一级入口一：决策

首页服务老板做判断，不服务老板翻流水账。

固定结构：

1. 最多 3 项需要老板决定或确认的事项；
2. 当前核心目标、阶段、阻塞和下一步；
3. 高风险或明显趋势变化；
4. 小优已经推进并有执行回执的结果；
5. 当前数据更新时间和可信度。

没有真实回执的内容不能写成“小优已完成”。候选、已入队、已送达、已回复和已核验必须分别展示。

### 7.2 一级入口二：经营

V1 只展示现有真实数据能够支撑的经营状态：

- 项目切换；
- 当前学生数及其数据状态；
- 当前记录和覆盖情况；
- 开放任务、逾期任务和完成证据；
- 早晚报交付状态；
- 有可靠时间序列时才展示趋势。
- 达到强证据门槛的学生成长与托管服务新项目机会，放在经营指标之后、项目列表之前。

新项目机会固定遵守以下产品边界：

- 最近30天有效记录覆盖率不低于60%；
- 涉及学生不少于 `max(5, 当前在读学生数的8%)`，证据跨至少3个日期和2名责任老师；
- 结构化记录类型和关注标签是主要证据，正文关键词不能单独触发；
- 机会卡明确区分“内部证据、小优判断、待老板决定”，候选不等于正式立项；
- 未达到门槛的弱信号只在内部观察，不进入 H5 和日报；
- 老板没有在企业微信确认前，小优不联系员工、不创建验证任务、不启动试点；
- H5 只读，点击后只复制问题并返回企业微信与小优继续处理。

V1 不展示伪造的续费概率、流失预测、招生漏斗或收入预测。

### 7.3 一级入口三：团队

固定能力：

- 在职、离职、状态待确认人员摘要；
- 店长和老师当前需要支持的事项；
- 影响学生服务的团队卡点；
- 经过提炼的员工声音趋势和中高风险信号，仅在底层证据成熟后进入 V1.1。

不展示员工完整聊天原文，不把员工声音直接变成绩效判断。

### 7.4 一级入口四：小优

该页不是技术监控台，而是老板查看数字员工工作结果的窗口。

固定能力：

- 今日早报和晚报是否生成、入队、送达或失败；
- 小优当前正在推进、等待回复和已经核验的事项；
- 主动联系的对象、原因和真实送达状态；
- 失败、结果未知和需要老板介入的事项；
- 小优最近基于证据修正了什么。

技术健康、模型耗时和工具错误详细信息放入 V1.1 的维护视图，不占老板日常首页。

### 7.5 老板二级页面

- 目标详情；
- 风险和证据详情；
- 项目详情；
- 小优执行回执详情。

工资、规则和数据质量管理不作为 V1 一级入口。底层数据和权限成熟后，可在 V1.1 增加老板私有管理页。

## 8. 数据来源冻结

### 8.1 A 类：权威业务事实

| 数据源 | V1 用途 | 约束 |
| --- | --- | --- |
| `students.json` | 学生身份、归属和有效状态 | 只展示角色授权范围 |
| `staff.json` | 人员角色和在职状态 | 状态未知必须显式标记 |
| `wecom_whitelist.json` | 企业微信授权和身份核验 | 只用于鉴权，不能单独作为人员展示真相 |
| `tasks.json` | 任务对象、责任人、状态和时间 | 取消、完成、过期任务不得作为当前重点 |
| `records.json` | 学生服务和老师工作证据 | 必须显示时间和来源 |
| `summer_enrollments.json` | 暑假项目学生范围 | 作为项目数据，不硬编码页面 |
| `summer_lesson_records.json` | 暑假项目课节证据 | 需按项目和人员权限过滤 |
| `growth_reports.json` | 已审核成长报告 | 家长可见内容只允许 approved 状态 |

### 8.2 B 类：执行与送达证据

| 数据源 | V1 用途 | 约束 |
| --- | --- | --- |
| `task_closure_events.json` | 任务关闭和补证据状态 | 与任务权威状态一致后展示 |
| `notification_outbox.json` | 消息入队、发送和失败状态 | 不把 pending 写成已送达 |
| `daily_report_runs.jsonl` | 早晚报生成与交付状态 | 展示最近有效运行 |
| `action_executions.jsonl` | 小优行动执行证据 | 仅聚合必要字段 |
| `business_action_audit.jsonl` | 审计追溯 | 体量较大，H5 只读聚合，不直接加载原文件 |

### 8.3 C 类：AI 候选与内部材料

以下数据可以辅助小优判断，但不能直接作为事实卡片：

- `hermes_work_items.jsonl`
- `attention_threads.jsonl`
- `relationship_touch_candidates.jsonl`
- `value_progress_ledger.jsonl`
- `goal_actions.jsonl`
- 员工声音、事实缺口、外部学习、市场观察、自我进化等候选账本

进入 H5 前必须经过：事实核验、角色权限、时效检查、对象状态检查和证据聚合。

### 8.4 D 类：派生和展示缓存

- `dashboard_cache.json`
- 绩效、工资、覆盖率、经营机会和每日简报等派生投影

D 类数据可重建，不能成为第二套业务真相。缓存生成时间和源数据更新时间必须分别展示，不能用“刚生成缓存”掩盖“源数据十天未更新”。

### 8.5 数据禁入项

V1 H5 不展示：

- 企业微信完整聊天原文；
- 员工声音原始文本；
- 老板、店长、老师的私人工作方式档案全文；
- 自我进化原始思考过程；
- 模型提示词、工具清单和 Hermes 技术信息；
- 未审核的家长报告；
- 无来源、无时间或无对象的 AI 结论。

## 9. AI 内容契约冻结

H5 中的 AI 内容统一标记为“小优判断”，并必须携带：

- 简短结论；
- 支持该判断的证据引用；
- 证据最后更新时间；
- 小优生成时间；
- 当前适用角色和项目；
- 置信度或“证据不足”状态；
- 建议用户继续查看，还是返回企业微信沟通。

以下情况不得进入重点区域：

- 无证据；
- 证据过期；
- 任务已取消或已完成；
- 员工已经离职；
- 学生不在当前项目或角色范围；
- 只是模型候选，还没有执行回执；
- 外部市场观察被错误当成示例机构内部事实。

## 10. 旧模块处置冻结

| 现有模块或表达 | V1 决定 | 原因 |
| --- | --- | --- |
| 今日 | 重构保留 | 按角色展示当前事实和下一步 |
| 绩效树、成长树、树形动画 | 从 V1 删除 | 容易制造监督感，且现有数据不足以支持可信绩效判断 |
| 绩效预估 | 从 V1 删除 | 当前规则和证据不足，缺失值容易被误算为零 |
| 我的素材 | 改为“我的积累” | 强调帮助老师沉淀工作，而非素材仓库 |
| 课节记录 | 合并到项目详情或学生详情 | 不为暑假项目建立永久独立导航 |
| 重点孩子 | 保留并并入“学生”默认视图 | 以真实原因和时效驱动 |
| 孩子覆盖 | 修正口径后进入 V1.1 | 当前按记录数除学生数，可能超过 100% |
| 店内状态 | 重构为“今日现场” | 从数据陈列改为异常和协作优先 |
| 老师支持 | 合并到“团队” | 以谁需要帮助和证据缺口组织 |
| 遗留任务 | 合并到“任务”状态分组 | 不让历史问题成为永久一级入口 |
| 目标、风险 | 合并进入老板“决策”及二级详情 | 老板首页先做取舍，不先浏览模块 |
| 工资、规则、资料 | 移出 V1 一级导航 | 未来作为老板私有管理页评估 |
| 旧 `opportunities` 关键词机会 | 删除展示 | 只统计“数学、阅读”等词，可能把正向进步误判为薄弱 |
| 强证据新项目机会 | 进入老板“经营” | 来自30天内部证据包与小优判断，明确标注待验证，不等于正式项目 |
| 学习候选 | 不直接展示 | 属于内部学习材料，不是经营事实 |
| “小优主动存在感” | 删除措辞 | 改为有回执的“小优已推进” |
| `暂无数据` | 删除通用文案 | 改为无问题、未采集、已过期、无权限或读取失败 |

现有前端中不可达的历史面板，在 V1 开发时从页面代码移除；底层函数先保留并记录依赖，不在产品重构中顺手删除生产能力。

## 11. 已确认的当前问题必须在 V1 修复

- 普通托管项目仍在运行，但店长页被硬编码成“冻结只读”。
- 老师覆盖率口径错误，可能超过 100%。
- 缓存更新时间与源数据更新时间混在一起。
- 缺失值被显示为 `0`。
- 老师首页以绩效树为主，却没有突出已生成的开放任务和小优陪伴材料。
- 老板和店长页面模块过多，重点不明确。
- 旧 attention、主动候选和工作项可能重新进入“今日”。
- 同一静态页面同时承担所有角色和历史面板，体积大、维护困难。
- 页面只有 Tab 和展开，没有清晰的“回企业微信问小优”协作出口。
- 页面存在 Hermes 技术名称和不统一的小优品牌表达。

## 12. 视觉系统冻结

V1 先冻结原则和基础 Token，具体高保真稿在结构确认后完成。

### 12.1 色彩

- 小优品牌绿：`#167A5A`
- 信息蓝：`#2F6FED`
- 警示黄：只用于需要关注但非危险的状态
- 风险红：只用于安全、严重逾期和明确失败
- 页面背景：浅中性色，不使用单一大面积品牌色
- 正文：深灰；次级信息：中灰；禁用和过期：浅灰

颜色不能单独承载状态，必须配合图标和文字。

### 12.2 字号与间距

- 页面标题：24px
- 区块标题：20px
- 卡片标题：17px
- 正文：15px
- 辅助信息：13px
- 间距基准：4 / 8 / 12 / 16 / 24 / 32px
- 卡片圆角：8px
- 点击区域最小高度：44px

### 12.3 组件原则

- 不在卡片中继续嵌套卡片；
- 首页重点卡片不超过 3 个；
- 列表优先于装饰性大卡片；
- 指标必须带口径、时间和数据状态；
- 不使用装饰性成长树、渐变球或大面积营销式 Hero；
- 底部导航固定，适配企业微信安全区域；
- 空状态必须说明原因和下一步，不使用笼统占位图。

### 12.4 品牌露出

- 页面首屏必须显示“小优工作台”；
- 可以设计简洁的小优文字标识或图形标识；
- 不显示 Hermes 名称、版本或模型名称；
- 角色通过副标题表达，不为每个角色建立不同品牌。

## 13. 移动端交互冻结

- 设计基准宽度覆盖 360、390 和 430px；
- 不允许一级导航横向滚动；
- 不允许正文横向溢出；
- 重要状态一屏可扫描，不依赖连续展开多个折叠区；
- 详情使用独立页或底部抽屉，不使用复杂弹窗；
- 搜索、筛选和项目切换使用标准控件；
- 返回企业微信的入口在关键详情和首页均可到达；
- H5 不内嵌第二个聊天框；
- 页面加载、鉴权失败、数据读取失败均有明确恢复方式。

## 14. 版本边界冻结

### 14.1 V1：当前真实能力立即可落地

- 三角色独立信息架构；
- 教师 3 个、店长 4 个、老板 4 个一级入口；
- 当前学生、人员、任务、记录、项目和执行回执的角色化展示；
- 小优有证据的今日重点和已推进事项；
- 数据状态、新鲜度和证据详情；
- 小优统一品牌；
- 返回企业微信继续协作；
- 只读 H5，不新增业务写入。
- 老板经营页的新项目机会：仅展示达到强证据门槛的学生成长与托管服务方向，最多3项。

### 14.2 V1.1：底座已有但需要少量只读聚合

- 统一角色化 `WorkbenchProjection`；
- 按源数据分别计算更新时间和过期状态；
- 正确的唯一学生覆盖率；
- 在职人员和有效责任关系过滤；
- 老板可见的小优健康摘要；
- 经过脱敏和证据核验的员工声音趋势；
- 机构地图和事实缺口摘要；
- 目标行动和执行回执聚合；
- 企业微信可用时的明确跳转或可见预填问题；
- 老板私有工资、规则和数据质量管理页的可行性评估。

V1.1 仍然只读，不建立第二套业务状态。

### 14.3 V2：业务事实成熟后再进入

- 招生线索与试听漏斗；
- 续费、流失和转介绍的权威业务账本；
- 有足够历史数据的趋势与预测；
- 多门店对比和经营分析；
- 有来源的外部市场洞察；
- 经单独权限和安全评审后的少量确定性 H5 操作。

V2 不能为了页面完整提前制造假数据、假预测或假入口。

### 14.4 永久边界

以下方向不进入小优工作台：

- 将 H5 变成 Hermes 控制平面；
- 为 H5 新建第二套任务、目标或人员状态；
- 用按钮背后的固定工作流替模型做业务判断；
- 展示员工完整对话或原始私人情绪材料；
- 将 AI 文本直接当成事实；
- 未经单独授权联系家长；
- 在 H5 直接修改工资、权限、制度或系统配置。

## 15. 开发验收标准冻结

### 15.1 产品验收

- 老师一级入口固定为 3 个；
- 店长一级入口固定为 4 个；
- 老板一级入口固定为 4 个；
- 每个角色首页都能在首屏回答“现在最重要什么、小优做了什么、我下一步做什么”；
- 任一一级模块都能说明它帮助用户完成哪项真实工作；
- 不出现无真实数据支撑的未来功能。

### 15.2 数据验收

- 后端继续执行角色权限隔离，不能只依赖前端隐藏；
- 每项重点有来源、更新时间和数据状态；
- 缺失不等于零；
- 过期、取消、完成、离职和越权对象不进入当前重点；
- AI 候选与业务事实有明确视觉区别；
- H5 缓存可完全重建。

### 15.3 交互与视觉验收

- 360、390、430px 宽度无横向溢出；
- 底部导航稳定，触控区域不小于 44px；
- 不出现卡片套卡片；
- 不使用横向滚动一级 Tab；
- 加载、无问题、未采集、已过期、无权限和失败状态分别设计；
- 页面不出现 Hermes 技术品牌；
- 页面不会因为长姓名、长任务名或动态数字改变布局。

### 15.4 运行验收

- 使用老师、店长、老板真实角色签名链接分别验收；
- H5 不产生业务写操作；
- API 未授权访问继续返回拒绝；
- 页面不一次性下载与当前角色无关的完整数据；
- 生产 canary 通过后再全量替换现有 H5。

## 16. 变更控制

本冻结稿确认后，开发遵循以下规则：

1. 不增加一级页面和一级导航。
2. 不把已删除模块换名后重新塞回首页。
3. 不为了视觉完整制造数据。
4. 不为 H5 新建业务写状态。
5. 不改变小优模型主导、系统守边界的核心理念。
6. V1 开发中发现数据不足时，降级为正确空状态或进入 V1.1，不用估算值填补。
7. 涉及角色权限、业务写入、家长触达或 Hermes 主链的变化，必须另立计划审批。

## 17. 冻结结论

V1 不再做一个“什么都能看”的数据看板，而是做三个角色各自愿意打开的 **小优工作台**：

- 老师得到帮助、任务陪伴和个人积累；
- 店长看到现场断点、学生服务和团队协作；
- 老板看到需要做的决定、真实经营状态和小优的执行结果；
- 小优仍在企业微信中理解、判断和行动；
- H5 只把真实事实和执行证据整理得清楚、可信、可持续查看。

确认本冻结稿后，下一步只进入：信息架构线框图、数据字段映射和移动端视觉原型。完成原型评审后才进入代码开发。
