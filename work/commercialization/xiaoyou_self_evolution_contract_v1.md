# 小优自我进化契约 V1

## 一句话目标

小优不是固定模板机器人，而是托管机构数字员工：白天工作，晚上复盘，夜间沉淀经验，第二天把已经验证的低风险经验带入服务。

## 不变原则

- 模型负责理解、判断和行动选择；系统不写 Router、不预设业务步骤、不替模型决定下一步。
- 系统只做身份、权限、审计、幂等、写后反查、频率、外发边界和候选沉淀。
- 小优可以学习工作方式、错误修正和明日重点；不能自动学习成制度、权限、工资、家长外发或正式手册。
- 低风险经验可以进入次日上下文；中高风险经验只进入审核候选。
- 夜间以复盘和候选沉淀为主，不真实外发，不派任务，不迁移业务数据。

## Hermes 能力在小优里的对应关系

- Skills：员工手册、稳定工作方法和岗位知识。
- Memory/账本：人员偏好、机构事实缺口、错误修正、工具失败、长期经验候选。
- Cron/wakeup：早报、晚报、夜间复盘、次日计划。
- Toolsets：允许小优查业务工具、人员目录、只读学习材料；不开放生产终端、文件写入或绕过权限的能力。
- Multi-agent：顾问团只给建议，主小优采纳、拒绝或延期，不允许顾问直接写业务或外发。
- Hooks/logs：观察小优是否“查过才说查过、写后反查成功才说保存、失败要留痕”。

## 进化候选类型

- `person_preference_candidate`：某个人希望小优怎样服务自己。
- `institution_fact_gap`：小优发现机构事实缺口，需问事实归属人。
- `self_correction`：小优发现自己犯过的表达、判断或工具使用错误。
- `tool_failure_or_bug`：工具失败、能力缺口或重复失败信号。
- `handbook_method_candidate`：多次验证有效、可写入员工手册的工作方法候选。
- `tomorrow_focus`：明天应重点处理的工作方向。
- `multi_agent_adoption`：主小优对顾问建议的采纳、部分采纳、拒绝或延期记录。

## 当前差距与本轮补齐

| 能力 | 现状 | 本轮补齐 |
| --- | --- | --- |
| 工作方式偏好 | 已有个人工作方式档案和写后反查 | 纳入自我进化简报，作为次日上下文 |
| 员工自评 | 已有晚间自评 scorecard | 增加进化候选，记录“学到什么、别再犯什么” |
| 主动雷达 | 已能看机构/人员/目标/风险缺口 | 夜间复盘时作为进化材料，不再只是巡检材料 |
| Multi-agent | 已有顾问结果和主模型采纳机制 | 采纳/拒绝进入进化账本，保持顾问只建议 |
| 错误修正 | 已有诚实守卫和日志复盘 | 新增 `self_correction` 候选，次日提醒小优避免重复 |
| 手册进化 | 以前靠人工改文档 | 新增手册候选，人工确认后再改正式 Skills |
| 老板可见健康度 | 分散在日志/看板/报告中 | 新增只读查询工具查看进化账本和待确认候选 |

## 验收标准

- 夜间循环能读取进化简报并落 `self_evolution_events.jsonl`。
- 低风险经验能进入下一轮上下文，但不改变权限、制度、手册或外发边界。
- 中高风险候选必须保持待审核状态。
- 老板/店长可只读查询进化账本。
- 小优未写后反查成功前，不能说“已保存、记住了、以后按这个来”。
