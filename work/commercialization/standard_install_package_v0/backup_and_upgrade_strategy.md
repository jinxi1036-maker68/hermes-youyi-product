# 备份与升级策略 V0

目标：在“单机构隔离复制”阶段，让每家机构可以安全升级、回滚和恢复，同时不覆盖机构数据。

## 1. 备份范围

每家机构必须独立备份：

- `config/`
- `data/`
- `skills/`
- `memory/`
- `reports/`
- `logs/` 中最近必要日志

产品代码单独备份：

- `app/releases/{version}`
- `app/current` 指向版本
- systemd 模板

## 2. 日常备份

建议：

- 每天凌晨备份租户 `config/data/memory/skills`。
- 自主唤醒报告保留 7 天明细，之后压缩摘要。
- prewrite 备份保留 7 天明细，之后压缩。
- 核心业务账本不硬删。

## 3. 升级前备份

升级前必须生成：

```text
backups/pre-upgrade/{timestamp}/
  config/
  data/
  skills/
  memory/
  upgrade_manifest.json
```

`upgrade_manifest.json` 至少记录：

- tenant_id
- 当前产品版本
- 目标产品版本
- 备份时间
- 升级人或升级任务
- 验收结果

## 4. 升级规则

- 升级产品代码时，只切换 `app/current` 或更新产品发布目录。
- 不覆盖租户 `config/data/memory/skills`。
- 如果需要新增数据文件，只创建空白文件或由租户配置生成。
- 如果需要变更机构配置，必须生成迁移报告，不能静默覆盖。
- 写入守卫、权限和企业微信密钥必须升级后复查。

## 5. 回滚规则

回滚优先级：

1. 回滚产品代码版本。
2. 回滚租户配置。
3. 恢复租户数据备份。

原则：

- 不能因为代码问题删除业务账本。
- 外发失败或未知状态必须保留动作账本。
- 回滚后 Hermes 下一次醒来要重新读取事实，不执行旧决定。

## 6. 灰度升级

未来有多家机构后：

- 先升级内部 demo 租户。
- 再升级示例机构样板。
- 再升级 1 家试点客户。
- 观察早晚报、唤醒、H5、写入、外发 24 小时。
- 再批量升级其他机构。

## 7. 恢复验收

恢复或回滚后必须检查：

- Hermes 服务 active。
- 企业微信能收发。
- H5 能访问。
- 早晚报和唤醒 timer active。
- 租户数据目录没有串机构。
- 最新业务账本仍可读。
- 写入守卫测试通过。
