# 新机构资料采集表 V0

目标：在生成新机构租户包前，收集足够的机构事实和权限边界。缺失资料可以留空，但必须明确是谁后续确认。

## 1. 基础资料

| 字段 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- |
| tenant_id | 是 | demo_tuoguan | 短 ASCII 标识，只能用于配置和目录。 |
| 机构名称 | 是 | 某某托管 | 小优对外识别当前机构的名称。 |
| 城市/校区 | 建议 | 郑州某校区 | 用于本地化业务判断。 |
| 当前阶段 | 建议 | 暑假班/秋季开学前 | 影响目标和提醒节奏。 |
| 老板当前目标 | 建议 | 续费、招生、服务稳定 | 可以为空，首次启动后由小优向老板确认。 |

## 2. 人员和账号

| 角色 | 必填 | 需要内容 |
| --- | --- | --- |
| 老板 | 是 | 姓名、企业微信 user_id、是否 super_user。 |
| 店长 | 建议 | 姓名、企业微信 user_id、权限范围。 |
| 老师 | 试点需要时 | 姓名、企业微信 user_id、是否进入灰度。 |
| 家长 | 否 | 第一阶段不要求导入，自动发送默认关闭。 |

## 3. 运营事实

- 机构服务类型：晚托、午托、周末、寒暑假班等。
- 常见风险：安全、作业、纪律、接送、家校沟通、续费。
- 老板规则：哪些事必须老板确认，哪些事可由店长确认。
- 店长职责：现场管理、老师协调、家长沟通边界。
- 老师职责：记录、反馈、风险上报、学生跟进边界。

## 4. 数据导入原则

- 可以导入少量试点学生和老师资料。
- 不导入优益样板数据。
- 不导入历史聊天记录。
- 不导入真实企业微信密钥明文。
- 运行账本必须从空白开始。

## 5. 缺失资料记录

| 缺失项 | 影响 | 后续确认人 | 是否阻塞启动 |
| --- | --- | --- | --- |
| 老板当前目标 | 小优无法主动围绕目标组织工作 | 老板 | 否 |
| 企业微信 user_id | 对应角色无法真实收发 | 老板/技术交付 | 是 |
| 店长权限范围 | 店长助手灰度范围不清 | 老板 | 否 |

## 6. 交付前确认

- 老板确认小优第一阶段不会自动联系家长。
- 老板确认高风险动作必须先说明依据和确认项。
- 老板确认试点以真实价值证据复盘。
- 技术交付确认 tenant profile 不含明文 secret/token/credential。
