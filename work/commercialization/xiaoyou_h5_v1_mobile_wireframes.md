# 小优 H5 V1 移动端线框

> 版本：V1.1
>
> 状态：待原型评审
>
> 说明：线框只定义信息顺序和交互层级，不代表最终视觉稿。

## 1. 共用移动端框架

```text
┌──────────────────────────────┐
│ [小优] 小优工作台    角色标签 │
│        机构 / 当前项目        │
│ 数据状态 · 最后更新时间       │
├──────────────────────────────┤
│                              │
│ 当前角色页面内容              │
│                              │
│ [返回企业微信问小优]          │
│                              │
├──────────────────────────────┤
│ 图标+一级入口的稳定底部导航   │
└──────────────────────────────┘
```

共用规则：

- 首屏只放当前最重要的1至3项；
- 事实与“小优判断”视觉上明确区分；
- 每项都有时间或数据状态；
- 需要写业务时回企业微信，不在H5模拟聊天；
- 详情使用独立页或底部抽屉；
- 无问题、未采集、已过期、无权限和失败分别设计。

## 5. 详情层级

详情页只显示当前对象所需证据：

| 详情 | 固定顺序 |
| --- | --- |
| 学生详情 | 当前状态、责任关系、开放任务、近期记录、更新时间 |
| 任务详情 | 来源、目标、对象、责任人、时间、陪伴阶段、证据要求、关闭状态 |
| 目标详情 | 老板原目标、当前阶段、已核验证据、阻塞、下一步 |
| 新项目机会详情 | 共同问题、汇总证据、门槛状态、小优判断、缺失事实、验证方案、边界 |
| 小优执行详情 | 候选、已入队、已送达、已回复、已核验或失败的真实状态 |
| 记录详情 | 学生、类型、事实摘要、老师动作、时间、可用场景 |

## 6. 原型评审问题

原型评审只判断：

1. 每个角色首页重点是否正确；
2. 一级导航是否符合真实工作频率；
3. 页面是否让老师感到被帮助，而非被考核；
4. 店长是否能先看到现场断点；
5. 老板是否能快速完成经营判断；
6. 小优的工作结果是否以回执而不是自述呈现；
7. 是否存在不应进入V1的假数据或未来能力。
