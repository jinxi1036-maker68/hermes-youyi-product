# Hermes 商业化分层准备 V1

本目录用于把当前优益样板中的 Hermes，整理成未来可复制给其他托管机构的产品交付骨架。

如果你是第一次打开本目录，先看：

- `START_HERE_小优第二家机构演示入口.md`：告诉项目负责人当前阶段、演示顺序、客户感兴趣后的下一步。

当前阶段不是正式 SaaS 平台，也不是新机构自动部署脚本。本阶段只做分层、模板、清单和风险识别，避免未来把优益专属资料、聊天记录、学生数据、企业微信密钥或调试历史复制给新客户。

## 当前定位

Hermes 商业化第一步采用“单机构隔离复制 + 标准化配置”：

- 一套标准 Hermes 产品能力。
- 每家机构独立数据、独立记忆、独立企业微信配置、独立 H5 权限。
- 开通新机构时填写机构资料模板，而不是复制优益数据。
- 等优益跑稳并完成 1-3 家试点后，再进入中央运维后台和真正多租户平台。

## 文件说明

- `product_layering_map.md`：产品通用、托管行业通用、机构专属、优益专属、实验能力、禁止复制的分层图。
- `tenant_onboarding_checklist.md`：新机构开通前必须收集的信息清单。
- `tenant_profile.template.json`：新机构配置模板。
- `delivery_package_manifest.md`：未来交付一个新机构 Hermes 时需要复制、生成、隔离、禁止携带的材料。
- `youyi_specific_inventory.md`：当前优益专属内容清单和已知写死点。
- `commercial_readiness_backlog.md`：商业化前需要修复或补齐的技术债。
- `standard_install_package_v0/`：未来新机构标准安装包 V0 设计，包括目录结构、初始化流程、生成文件规则、首次启动验收、备份升级和安装脚本蓝图。
- `sales_demo_package_v0/`：面向第二家机构老板的成交演示材料。
- `maintenance_package_v0/`：生产巡检、最小升级和回滚维护手册。

## 使用原则

- 这里的模板不改变当前优益生产配置。
- 这里的内容不自动进入 Hermes 普通聊天上下文。
- 新客户交付时必须先完成数据隔离、记忆隔离、企业微信隔离和备份恢复检查。
- 优益真实业务资料只能作为样板经验，不能直接复制到其他机构。
