# 小优真实数字员工闭环 V1 对抗审查

日期：2026-08-13
基线：Hermes v0.20.0 + Agnes 2.5 Flash

## 一、结论

本轮不是增加一个“主动提醒”功能，而是补齐从经营目标到真实结果的持久执行链。代码已经通过固定回归、语法检查、敏感扫描和 demo 租户验收。生产只允许先部署金总与李老师灰度；店长和全体老师必须等待自然链路验收，不提前开放。

## 二、对抗发现与修复

| 级别 | 攻击或故障场景 | 修复结果 |
|---|---|---|
| P0 | 老板口头授权只变成普通事实，执行器仍认为不能找老师 | 新增正式主动授权账本和查询/调整/撤销工具，写后反查后才生效 |
| P0 | 模型生成主动候选后停住，却说“我现在就去找” | 新增候选执行工具和候选/入队/发送三级诚实守卫 |
| P0 | 撤销授权后，旧 pending 消息仍可能发送 | 撤销时停止 pending/retry；sending 标为 `result_unknown`；发送前再次复核授权 |
| P0 | 员工离职或被移出白名单后，已排队消息仍发送 | outbox claim 前重新核验角色、在职状态、灰度和时间窗，不通过即 suppressed |
| P0 | outbox 已失败却被重复执行接口说成 queued | 按真实 outbox 状态反写 `failed/result_unknown/superseded`，不误报 |
| P0 | 老板确认目标后只留下静态方案，没有可恢复行动 | 新增目标行动账本；没有具体行动时自动建立事实基线核查 |
| P0 | 模型可把学生任务派给不负责该学生的老师 | 正式目标子任务强制核验学生服务类型和主责老师；关系不清先补事实 |
| P0 | 自主创建任务后，老师回复无法挂到任务 | 同时写入老师活动任务、下一任务和会话焦点并反查 |
| P0 | 老师完成任务，但目标行动仍永久等待 | 任务反馈同步目标行动；完整事实进入 `replied_sufficient` |
| P0 | 完整回复直接从待办消失，没有结果验证 | 回复充分后仍保留为开放行动；主模型核验后才 `verified -> resolved` |
| P0 | 行动闭环但目标覆盖进度没有变化 | 核验证据时按学生写入目标进度并再次反查 |
| P0 | 重复唤醒、重复候选或重复回调轰炸员工 | outbox id、行动语义指纹、每日频率和发送 lease 共同幂等 |
| P0 | 目标撤销后行动、候选和提醒继续运行 | 追加取消/替代状态并停止未发送 outbox；不删除历史 |
| P1 | 同一授权调频被旧指纹当成幂等 | 授权指纹纳入频率和有效期；同范围调整写成正式更新事件 |
| P1 | 错误把“自主决定找谁”保存成语气偏好 | 修复脚本追加语义失配状态，工作方式读取时忽略该记录 |
| P1 | 旧李老师候选和“等待全名/看板方式”重新复活 | 修复脚本只追加 `superseded` 和当前状态更正，不补发旧消息 |

- 上线前必须备份代码、任务、outbox、目标、主动候选、工作方式、主动授权和目标行动账本。
- 历史修复脚本先 dry-run，确认只命中旧未发送候选、错误工作方式语义和失效等待，再 apply。
- 同步 runtime、lib、lib64 和 Home 插件副本；严格加载检查必须包含 `proactive_work.py`、`goal_operator.py` 和自主循环。
- 只执行一次受控主服务重启；不手动触发真实外发。
- 上线后检查服务、v0.20、Agnes 2.5、工具数、哈希、日志、outbox 和自然自主唤醒。

## 五、仍需自然观察

- 第一灰度必须真实完成三条“发送 -> 李老师回复 -> 目标证据更新”链路并观察 48 小时。
