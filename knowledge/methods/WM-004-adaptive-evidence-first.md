# WM-004｜Adaptive Evidence-First Project Method

- Status: Current
- Effective: 2026-09-26
- Machine authority: `knowledge/WORKING_METHOD.json`

## 这次升级解决什么

Project Knowledge V2 已经解决“项目事实连续性”，但还缺“工作方式连续性”。

如果新窗口：
- 知道项目路线；
- 知道当前 blocker；
- 却重新改变分工、验收节奏、Codex使用方式或部署纪律；

项目仍然会发生隐性分裂。

## Decision

把 Working Method 正式作为 Project Knowledge 的一等资产：

- 当前方法有唯一版本；
- 方法可迭代；
- 每次变化必须有原因；
- 旧方法不删除；
- 新窗口必须继承当前方法；
- 方法更新也需要 Evidence / Learning 思维。

## 新增的核心机制

**Method Learning Loop**

```text
流程摩擦/重复失败
→ 判断是否真是工作方式问题
→ 候选方法
→ 有边界地验证
→ 评估正确性/速度/安全/返工
→ accept/reject
→ accept 后升级方法版本
→ 保留历史
→ Knowledge Sync
```

## 成功标准

长期目标不是规则越来越多，而是：

- 更少重复错误；
- 更少人工传话；
- 更快定位真实 blocker；
- 更少无证据生产重试；
- 更稳定的跨窗口接班；
- 同等安全下更短的工作路径。
