# 测试、证据与封板制度

## 第一性原理

每个阶段开始前先回答：
1. 这一阶段只证明什么？
2. 为什么现在证明？
3. 上一阶段哪些已经封板？
4. 下一阶段哪些现在不能做？
5. 什么最小真实实验足够证明能力？

## 冻结标准

第一次用户测试前冻结：
- PASS
- FAIL
- blocker
- non-blocker

测试中不得因为每个新细节无限移动终点线。

## Blocker

直接违反冻结标准，并且改变：
- 事实
- 权限
- 决策
- 阶段边界
- 真实执行
- 安全
- 数据完整性

必须修复和复测。

## Non-blocker

例如：
- 措辞
- 展示
- 轻微精度
- 不改变判断的体验问题

进入 backlog，不阻塞封板。

## 基线 A/B

候选失败时：
- 必须在稳定基线跑相同测试；
- stable 同样失败 = 既有问题；
- 只有 candidate-only failure 才算候选回归。

## 证据层级

从弱到强：
1. 模型自述
2. 单元测试
3. 隔离集成测试
4. 服务器真实候选运行
5. 生产技术门禁
6. 用户真人业务验收
7. 跨会话/跨重启/长稳恢复

关键业务能力不能停在 1-3 就宣称正式 PASS。

## 封板流程

```text
定义阶段命题
→ 冻结验收
→ 用户首次测试
→ PASS/FAIL
→ 只修 blocker
→ 必要复测
→ 恢复/稳定性验证
→ 最终 PASS 记录
→ merge main
→ stable tag
→ 封板
→ 下一阶段
```

## 封板后

非关键小波动不重新打开。
只有：
- 真实架构缺陷；
- 后续阶段证明前提错误；
- 安全/权限/数据真实性回归

才重新评估已封板阶段。
