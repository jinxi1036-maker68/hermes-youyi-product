# 架构与不可破坏边界

## 核心调用关系

```text
自然语言
  ↓
模型 / 小U业务大脑
  - 理解
  - 判断
  - 规划
  - 选择行动
  - 面向用户表达
  ↓
能力 / Tool
  ↓
XiaoYou Core
  - 身份
  - 权限
  - tenant隔离
  - 对象存在性
  - 幂等
  - 执行
  - 回执
  - 写回验证
  - 审计
  ↓
Institution Workspace / 权威业务数据
```

## 唯一业务大脑原则

**模型是唯一业务大脑。**

后台可以强制：
- 身份
- 权限
- tenant 边界
- 日期/数学等确定性计算
- 幂等
- 高风险确认
- 真实执行结果
- 写后反查
- 审计和恢复

后台不应该：
- 用关键词 Router 替模型理解业务意图；
- 逐场景写固定业务决策树；
- 替模型决定“先做什么、为什么”；
- 生成第二套隐形业务脑。

一句话：**大脑可以自由想，手不能乱伸。**

## Runtime 可替换原则

长期结构：

```text
AI Runtime / Model（可替换）
        ↓
薄的 XiaoYou Runtime Adapter
        ↓
XiaoYou Core（稳定）
        ↓
业务能力
        ↓
Institution Workspace
```

模型、Hermes、渠道都可替换；产品核心能力不能绑死在某一厂商。

## Channel 只是适配器

企业微信、飞书、Web、Robot、语音是通道，不是业务能力本身。

## H5 边界

H5 是展示/洞察层，不能反向成为业务真相源。

## Knowledge / Memory / Learning 边界

长期定义：

- **Business Truth**：当前真实业务事实。
- **Knowledge**：机构制度、方法、标准、经过治理的经验。
- **Memory / History**：过去发生过什么、与谁发生、历史上下文。
- **Learning**：如何把纠错和结果转化为候选经验，再经过验证进入 Knowledge。
- **Goal / Work State**：当前要完成什么、卡在哪、何时继续。
- **Model Reasoning**：基于上述内容决定下一步。

知识可以增长，但**单次模型上下文必须有预算**。不能把整个知识库塞给模型。

## 不允许的架构退化

- 不为每个业务写一个 Router。
- 不因为安全把所有日常动作重新要求老板逐项确认。
- 不把 Unknown 写成 0 / 没有 / 没发生。
- 不把“Tool 发起”说成“已经完成”。
- 不把 API accepted 说成“对方已经看到/执行”。
- 不让程序伪造业务判断。
